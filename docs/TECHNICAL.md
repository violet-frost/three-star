# 技术说明

## 交付与基准

版本 `0.2.1-web`。规则依据《游戏策划案》V0.2执行版；美术遵循用户确认的参考图造型与配色。与旧《设计思路》冲突时，采用独立阵型按钮、移动中自动攻击、180秒和当前三英雄规则。

用户追加的随机地面星尘是本版新增资源渠道。原案213点资源上限不再适用于开启随机星尘的对局。野怪、星核、淘汰掉落规则保留；关闭 `Config.scatter.enabled` 可回到原有资源渠道。

交付包含可运行网页、所有源码资源、技术与配置说明；无需引擎编辑器、npm安装、云服务或编译步骤。

## 架构和状态

经典JavaScript脚本按 `config → rules → simulation → render → audio → app` 加载，共用 `globalThis.ThreeStar` 命名空间，避免file协议下ES模块和fetch的跨域限制。游戏无外部脚本、远程字体、远程图片或统计请求。

`Simulation(seed)` 完全独立于浏览器DOM，可在Node中运行相同规则。`App`持有输入、界面和对局对象，`Renderer`只读取战斗状态，`AudioEngine`响应事件。UI排序不能反向决定排名。

应用状态为 `menu / countdown / playing / paused / result`。淘汰观战作为playing状态下的视角切换，因此AI和战斗继续推进。开始新局总是创建全新Simulation，无复用英雄、资源或技能冷却。

## 时间和事件顺序

逻辑步长1/30秒；requestAnimationFrame驱动累积器，画面独立绘制。单次呈现延迟最多补算0.25秒；长时间后台通过失焦/可见性事件主动暂停，不通过后台快进补战斗。

每步主要顺序：生成到期资源事件、AI和输入、中心及英雄移动、间距修正、索敌、动作/技能执行、弹道与区域、暗幕、伤害死亡批次、拾取、占领、觉醒、胜负。180秒完成到时帧后冻结。资源事件与死亡后拾取采用确定性ID及稳定顺序。

普攻、技能冷却从前摇开始。前摇失效消耗本次冷却；换阵不重置攻击和技能。已产生弹道保存攻击快照，施法者死亡仍可命中。已生成绊索在施法者死亡后继续存在。

暗幕按5/10/20HP每秒分段积分；每英雄记录小数余量，以0.01HP为量化单位，避免30Hz逐次取整把5HP/s变成5.1HP/s。护盾、防御及圆阵均不抵挡暗幕。

## 移动和导航

小队中心移动速度180世界px/s，输入超过0.15死区后方向归一化、全速移动。中心导航半径90，英雄碰撞半径12；英雄槽位随最后有效移动方向旋转。换阵0.30秒插值，逻辑资格即时更新。二人、孤军使用对应槽位，孤军速度另乘1.10。

英雄回位以最低360px/s的修正能力追赶，单帧修正不超过12px。障碍移动采用小步扫掠与沿轴滑动，防止高速穿越矩形。单位两次局部分离迭代减少重叠，英雄受击退或突进时暂停回位。

地图仅有配置表内四个矩形内部障碍，真实碰撞与渲染一致。导航采用扩大矩形顶点的可见图与最短路，替代原案建议的网格导航；适合本版四个固定障碍，支持中心90及英雄12两种半径。若增加不规则地形，建议替换为导航网格或A*栅格。

固定纵向视野960世界px，横向按容器比例适配；镜头平滑0.15秒并夹取地图边缘，不自动缩放。小地图提供对局总览，是为网页试玩增加的辅助信息；正式竞技可按设计方向限制其敌队信息。

## 战斗和死亡批次

英雄独立记录生命、动作、目标、攻击/技能就绪时间、减速、护盾、强化标记与死亡时间。战斗伤害为 `max(1, ATK−DEF) × 技能 × 阵型 × 协同`，生命扣减到小数点后两位，飘字取整。

圆阵只保护最大命中数为1的普攻弹道，主目标70%，60px内队友均分30%。穿透弹、近战扇形、技能、野怪近战和暗幕不分摊。分摊后的份额分别进入护盾，不二次算防御、不递归分摊。

伤害队列处理后统一确认死亡。致死帧按对英雄有效生命伤害最多的队伍归属，同伤取较早事件；环境致死回溯5秒敌方来源。A09仅为本批次存活者提供护盾，不能复活同批次死亡者。全灭掉落携带量的50%并向下取整，其余计为移除量。

荧惑弹道按线段接触顺序命中；命中集合防止同一弹重复命中，碰墙、飞行距离耗尽或命中数达上限后回收对象。受出生保护单位不消耗穿透次数。野怪不能穿越障碍，脱战返营后1秒恢复满血。

## 资源与成长

携带星尘C用于当前HUD和存活排序，累计获得G用于觉醒。普通野怪3、精英10、星核15；散落星尘默认1。死亡英雄不单独掉落，只有全队淘汰掉落。

随机散落星尘使用与对局相同的种子随机数。初始80枚平均分布四象限；每20秒补12枚，未拾取散落包最多100枚，不含野怪及淘汰包。坐标避开障碍、边缘及相邻包，新增位置处于当前安全半径减70px以内。原已存在包不会因收圈被移动或销毁。刷新上限达到时跳过，不累积欠额。

所有地面包拥有唯一ID，按最近存活英雄所属队伍判定归属，同距按队伍ID。整包只拾取一次，无击杀专属权。资源守恒式：

```text
已生成资源 − 淘汰移除量 − 四队当前携带 − 地面未领取 = 0
```

星核每队独立进度2秒；多队暂停，离场清零。有效敌方英雄伤害清零并锁定0.5秒，占领成功后45秒刷新。出生保护英雄不参与。累计每25点进入觉醒队列，每队最多6次；三个不同ID、层数上限、英雄存活要求、10秒超时随机和AI选择都由Simulation处理。

## AI

三支AI同规则运行，宏观决策每秒一次。依次处理安全区、威胁下撤退、安全拾取、接战、星核、刷野、巡逻。读取全局公开星核和安全区，以及中心220px内单位和掉落；静态营地坐标预先已知。未到45秒不巡查尚未生成的精英营地；残血避免追打精英，受野怪威胁也能圆阵撤退。

短时目标保持和路径复用避免方向抖动。资源、死亡和星核事件可唤醒决策。AI未共享目标，不针对真人组队。数值和阈值在配置中可改；真人体验的最终平衡仍需实际试玩反馈。

## UI、触控、音频和本地数据

Canvas画世界，DOM画HUD和可访问按钮。摇杆使用独立pointerId与pointer capture。换阵和觉醒按钮对触摸pointerdown立即响应，抑制随后的兼容click，保证第二根手指可操作；鼠标和键盘正常使用click。暂停清空旧输入，恢复倒计时3秒，避免切回页面后小队持续移动。

音乐和音效均由Web Audio本地合成，不需要音频文件。首次用户操作后解锁音频。音效具有同类频率限制，振动仅在浏览器支持时调用。相比原案交付级音频，本版采用轻量合成曲与事件音色。

localStorage键：`three-star-settings`、`three-star-tutorial`、`three-star-logs`。最近最多20局完整事件日志，超出站点配额时移除最旧日志；存储不可用时继续本次会话，不阻断游戏。不会上传日志或保存中途对局。

## 开发和验证

```sh
node --test tests/*.test.cjs
node tools/serve.cjs
python tools/package.py
```

自动测试直接运行真实Simulation，覆盖伤害核算、圆阵、技能、协同、弹道遮挡、持续效果、分段暗幕、排名、资源守恒、随机星尘、占领与觉醒；固定种子20局完整运行。桌面和移动触摸模拟另使用 `tools/browser-check.cjs` 与 `tools/browser-interaction.cjs`。

浏览器脚本通过Chrome DevTools Protocol连接**专用测试Chrome**的9227端口，需先自行启动启用该端口的独立浏览器；日常运行游戏无需该端口或这些脚本。截图输出到output目录，不包含在运行包。

真实Android/iOS硬件、Safari音频策略以及低端手机性能没有在本机做实测，不将浏览器模拟结果作为真实设备结论。美术采用四向静态图集与程序动画、特效；角色不是原案完整逐帧动画资产库。网页目标是可修改、可验证的完整玩法原型。
