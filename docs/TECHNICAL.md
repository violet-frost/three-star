# 技术说明

## 交付与基准

版本 `0.3.5-web`。基础规则依据《游戏策划案》V0.2执行版；阵型以用户最新表格为准（V0.3.0），覆盖原案阵型倍率及专属效果；美术遵循用户确认的参考图造型与配色。与旧《设计思路》冲突时，采用独立阵型按钮、移动中自动攻击、180秒和当前三英雄规则。

用户追加的随机地面星尘是本版新增资源渠道。原案213点资源上限不再适用于开启随机星尘的对局。野怪、星核、淘汰掉落规则保留；关闭 `Config.scatter.enabled` 可回到原有资源渠道。

交付包含可运行网页、所有源码资源、技术与配置说明；无需引擎编辑器、npm安装、云服务或编译步骤。

## 架构和状态

经典JavaScript脚本按 `config → rules → simulation → render → audio → app` 加载，共用 `globalThis.ThreeStar` 命名空间，避免file协议下ES模块和fetch的跨域限制。游戏无外部脚本、远程字体、远程图片或统计请求。

`Simulation(seed)` 完全独立于浏览器DOM，可在Node中运行相同规则。`App`持有输入、界面和对局对象，`Renderer`只读取战斗状态，`AudioEngine`响应事件。UI排序不能反向决定排名。

应用状态为 `menu / countdown / playing / paused / result`。淘汰观战作为playing状态下的视角切换，因此AI和战斗继续推进。开始新局总是创建全新Simulation，无复用英雄、资源或攻击冷却。

## 时间和事件顺序

逻辑步长1/30秒；requestAnimationFrame驱动累积器，画面独立绘制。单次呈现延迟最多补算0.25秒；长时间后台通过失焦/可见性事件主动暂停，不通过后台快进补战斗。

每步主要顺序：生成到期资源事件、AI和输入、中心及英雄移动、间距修正、索敌、普攻动作执行、弹道、暗幕、伤害死亡批次、横阵治疗、拾取、占领、觉醒、胜负。180秒完成到时帧后冻结。资源事件与死亡后拾取采用确定性ID及稳定顺序。

普攻冷却从前摇开始。前摇失效消耗本次冷却；换阵不重置攻击冷却。已产生弹道保存攻击快照，施法者死亡仍可命中。荧惑的强化状态在实际发射时记录到弹道快照，换阵或施法者死亡不会消除已发射弹道的强化。

暗幕按5/10/20HP每秒分段积分；每英雄记录小数余量，以0.01HP为量化单位，避免30Hz逐次取整把5HP/s变成5.1HP/s。暗幕无视防御和护盾；圆阵会把伤害转交存活镇星，但不减少暗幕总伤害。

## 移动和导航

小队中心移动速度180世界px/s，输入超过0.15死区后方向归一化、全速移动。中心导航半径90，英雄碰撞半径12；英雄槽位随最后有效移动方向旋转。换阵0.30秒插值，逻辑资格即时更新。二人、孤军使用对应槽位，孤军速度另乘1.10。

英雄回位以最低360px/s的修正能力追赶，单帧修正不超过12px。障碍移动采用小步扫掠与沿轴滑动，防止高速穿越矩形。单位两次局部分离迭代减少重叠，英雄按普通跟随移动回位；旧突进和击退逻辑已删除。

地图仅有配置表内四个矩形内部障碍，真实碰撞与渲染一致。导航采用扩大矩形顶点的可见图与最短路，替代原案建议的网格导航；适合本版四个固定障碍，支持中心90及英雄12两种半径。若增加不规则地形，建议替换为导航网格或A*栅格。

固定纵向视野960世界px，横向按容器比例适配；镜头平滑0.15秒并夹取地图边缘，不自动缩放。小地图提供对局总览，是为网页试玩增加的辅助信息；正式竞技可按设计方向限制其敌队信息。

## 战斗和死亡批次

英雄独立记录生命、动作、目标、攻击就绪时间、护盾、阵型强化计数与死亡时间。战斗伤害为 `max(1, ATK−DEF) × 阵型攻击倍率 × 普攻强化倍率`，生命扣减到小数点后两位，飘字取整。

圆阵将所有来源的队友伤害转交本队存活镇星，包括普攻、野怪及暗幕。攻击伤害以镇星的防御重新计算一次，护盾由镇星消耗；暗幕仍绕过护盾。击杀归属和伤害统计以实际承伤者为准。镇星生命归零后，本批次后续伤害恢复由原目标承受；单次致死伤害的溢出部分按常规丢弃。控制效果已从当前版本移除。

## 阵型与专属效果（V0.3.0）

显示顺序及快捷键为1圆阵、2楔形、3横阵；内部ID保留0楔形、1圆阵、2横阵，由 `formationOrder:[1,0,2]` 映射。`initialFormation:0` 保持默认楔形。攻击/防御/中心移动倍率分别为：圆阵1.0/1.2/1.0，楔形1.5/0.8/1.0，横阵0.8/1.0/1.0。基础远程覆盖倍率均为1.0；原有A06觉醒仍可增加横阵覆盖。

镇星的“破阵”仅作为圆阵承伤标签，不再发动主动突进或击退。荧惑仅在楔形实际发射时累计火焰弹，第三发伤害乘2，整发穿透命中均享受强化；取消的攻击不计数，其他阵型发射不计数，换阵保留已有计数。不再附加旧破阵集火协同。旧的定时强化和额外蓄能穿透已移除。

重华在横阵且存活时累计治疗时间，每满1秒为当前生命值最低的受伤存活友军恢复2点，包含自身；相同生命以英雄ID稳定选择。治疗不超过生命上限，不复活，重华阵亡后停疗。换阵暂停并保留不足1秒的进度，满血时消耗当次治疗机会，不积攒多次治疗。开局保护结束后开始计时。旧绊索、普通攻击减速及A08延长减速均已移除。

表现包括镇星星盾与承伤连线、荧惑蓄能计数和金色强化火弹、重华绿色治疗加号/回血飘字与音效。横阵按钮、A06觉醒、操作手册和战绩统一引用新芽治疗SVG。

伤害队列处理后统一确认死亡。致死帧按对英雄有效生命伤害最多的队伍归属，同伤取较早事件；环境致死回溯5秒敌方来源。A09仅为本批次存活者提供护盾，不能复活同批次死亡者。全灭掉落携带量的50%并向下取整，其余计为移除量。

荧惑弹道按线段接触顺序命中；命中集合防止同一弹重复命中，碰墙、飞行距离耗尽或命中数达上限后回收对象。受出生保护单位不消耗穿透次数。野怪不能穿越障碍，脱战返营后1秒恢复满血。

V0.3.2按用户确认移除《游戏策划案》第06节对应的旧主动技能、协同和控制：不再有技能前摇、技能冷却、突进、击退、破阵集火或减速。保留普通攻击、三种阵型效果、开局保护及A09生存护盾。A07共鸣和A08缠绕标为停用，不投放、不接受选择；保留ID槽位以兼容日志。当前可选觉醒7种。

## 资源与成长

携带星尘C用于当前HUD和存活排序，累计获得G用于觉醒。普通野怪3、精英10、星核15；散落星尘默认1。死亡英雄不单独掉落，只有全队淘汰掉落。

随机散落星尘使用与对局相同的种子随机数。初始80枚平均分布四象限；每20秒补12枚，未拾取散落包最多100枚，不含野怪及淘汰包。坐标避开障碍、边缘及相邻包，新增位置处于当前安全半径减70px以内。原已存在包不会因收圈被移动或销毁。刷新上限达到时跳过，不累积欠额。

所有地面包拥有唯一ID，按最近存活英雄所属队伍判定归属，同距按队伍ID。整包只拾取一次，无击杀专属权。资源守恒式：

```text
已生成资源 − 淘汰移除量 − 四队当前携带 − 地面未领取 = 0
```

星核每队独立进度2秒；多队暂停，离场清零。英雄伤害不清零、不暂停或锁定占领进度；占领成功后45秒刷新。出生保护英雄不参与。累计每20点进入觉醒队列，每队最多6次；三个不同ID、层数上限、英雄存活要求、10秒超时随机和AI选择都由Simulation处理。

## AI

三支AI同规则运行，宏观决策每秒一次。依次处理安全区、威胁下撤退、安全拾取、接战、星核、刷野、巡逻。读取全局公开星核和安全区，以及中心220px内单位和掉落；静态营地坐标预先已知。未到45秒不巡查尚未生成的精英营地；残血避免追打精英，受野怪威胁且镇星存活时可圆阵撤退。安全且有人受伤、重华存活时使用横阵恢复；镇星阵亡后不选择无承伤者的圆阵。

短时目标保持和路径复用避免方向抖动。资源、死亡和星核事件可唤醒决策。AI未共享目标，不针对真人组队。数值和阈值在配置中可改；真人体验的最终平衡仍需实际试玩反馈。

## UI、触控、音频和本地数据

V0.2.2将提示收纳到上方 `.notification-stack`，顶部约为视口高度的17%，消息实际显示约20%处；重要消息或暗幕伤害警告出现时暂不显示教学，减少提示堆叠。左右英雄状态和小地图保留在边缘。淡黄半透明框统一通过 `style.css` 末尾的 Stardust glass 主题覆盖设置，CSS变量集中控制颜色、描边与阴影。图标使用本地SVG，通过 `iconMarkup` 在各界面共享，经典脚本与file协议支持保留。

Canvas画世界，DOM画HUD和可访问按钮。摇杆使用独立pointerId与pointer capture。换阵和觉醒按钮对触摸pointerdown立即响应，抑制随后的兼容click，保证第二根手指可操作；鼠标和键盘正常使用click。暂停清空旧输入，恢复倒计时3秒，避免切回页面后小队持续移动。

V0.2.3浮动摇杆监听 `game-shell` 的指针事件，排除按钮、英雄状态、觉醒、观战及弹窗区域；按下位置为固定锚点，本次拖动期间不随手指漂移。摇杆直径为战场宽度的48.72%，等于旧控件宽度87%×28%的两倍；摇杆自身不接收指针，手势由战场捕获。松开、取消、丢失捕获、暂停、淘汰、重开与窗口尺寸变化会清空方向并隐藏摇杆。键盘移动不显示摇杆。

队伍HUD名称由9px改为10px，存活人数由8px改为9px并显示N/3，星尘仍为18px。阶段标签与右侧阶段列表从HTML移除，正常时钟与暂停操作保留；阶段变化仍产生必要的短暂战场消息。

`Renderer.attackRange(sim,team)` 对存活英雄取 `英雄到队伍中心距离 + Simulation.attrs(hero).range` 的最大值，绘制以队伍中心为圆心的黄色虚线圆，表示射程外包络。只显示当前视角队伍；观战时随观战队伍切换，全灭时不绘制。圆圈无填充、不改变碰撞或索敌；圈内不是保证命中区域，具体仍由各英雄实际距离、目标与墙体遮挡决定。

音乐和音效均由Web Audio本地合成，不需要音频文件。首次用户操作后解锁音频。音效具有同类频率限制，振动仅在浏览器支持时调用。相比原案交付级音频，本版采用轻量合成曲与事件音色。

localStorage键：`three-star-settings`、`three-star-tutorial`、`three-star-logs`。最近最多20局完整事件日志，超出站点配额时移除最旧日志；存储不可用时继续本次会话，不阻断游戏。不会上传日志或保存中途对局。

V0.3.2将存活人数向左内缩6px，并把其字号9→11px；星尘数12→14px、进度9→11px、英雄名9→11px、英雄详情8→10px、星核倒计时9→11px。高度不超过650px时详情7→9px、倒计时8→10px。己方信息区宽38%、最多180px，详情不换行，教学提示向右收窄避免覆盖详情。

## 开发和验证

```sh
node --test tests/*.test.cjs
node tools/serve.cjs
python tools/package.py
```

自动测试直接运行真实Simulation，共35项，覆盖伤害核算、全来源圆阵承伤与阵亡回退、第三发双倍火弹、每秒最低生命治疗、移除旧技能与控制、停用觉醒过滤、弹道遮挡、分段暗幕、排名、资源守恒、随机星尘、占领与觉醒；固定种子20局完整运行。桌面和移动触摸模拟另使用 `tools/browser-check.cjs` 与 `tools/browser-interaction.cjs`。

浏览器脚本通过Chrome DevTools Protocol连接**专用测试Chrome**的9227端口，需先自行启动启用该端口的独立浏览器；日常运行游戏无需该端口或这些脚本。截图输出到output目录，不包含在运行包。

真实Android/iOS硬件、Safari音频策略以及低端手机性能没有在本机做实测，不将浏览器模拟结果作为真实设备结论。美术采用四向静态图集与程序动画、特效；角色不是原案完整逐帧动画资产库。网页目标是可修改、可验证的完整玩法原型。

V0.3.4：结算页所有文字字号增加2px，高度不超过650px的标题与星形标记也在原小屏字号上增加2px。保留纵向滚动及按钮访问。

V0.3.5：觉醒标题使用 `.awakening-title` 左图右名；卡片采用标题/描述/层数三行Grid，使三张卡片的描述顶部及层数底部对齐。所有7项有效觉醒的35种三选一组合已在390×844、360×640、1440×1000验证无横向溢出；实际选取正常。六枚新SVG由选择卡片和结算页共享；A07/A08仍停用。总览PNG及生成方法见素材说明。
